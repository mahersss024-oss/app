# تطبيق سوق حمد

تطبيق React Native وExpo SDK 58 لأندرويد وآيفون، بواجهات أصلية واتصال HTTPS مباشر بـAPI سوق حمد. لا يستورد صفحات Next.js ولا يستخدم WebView أو Capacitor. نسخة الويب متاحة لمعاينة الكود واختبار الواجهات أثناء التطوير فقط.

ملف Android التجريبي (local-only artifact; excluded from Git) بإصدار 1.0.3 لأجهزة arm64. ثُبّت على هاتف Android 15، وفتح الرئيسية وجلب إعلانات السوق من API مباشرة. طابقت الشاشة تصنيفات الويب وبطاقاته الأفقية وأيقونة حمد وشريط التنقل. لقطة الهاتف (local-only artifact; excluded from Git). الحزمة موقّعة محليًا للتجربة وليست جاهزة للمتجر؛ تصدير iOS نجح، لكن لم يُنشأ IPA موقّع.

إعداد الإصدار الإنتاجي الحالي هو `1.0.33`، build `34` على Android وiOS. مسارا Codemagic يجهزان AAB وIPA موقّعين عند الدفع إلى `main` بعد رفع شهادات التوقيع إلى Codemagic؛ راجع [إعداد Codemagic](docs/codemagic-release-setup.ar.md). تفاصيل التحقق السابق وحدود الاتصال بالسيرفر في [سجل التحقق](docs/native-mobile-verification-2026-10-23.ar.md).

## التشغيل

من هذا المجلد باستخدام Node 22.23.3 وpnpm 10.32.1:

```powershell
pnpm.cmd install --frozen-lockfile
Copy-Item .env.example .env.local
pnpm.cmd start
```

اضبط `EXPO_PUBLIC_API_URL` في `.env.local` إلى سيرفر التجربة الذي يحتوي إضافات API المصاحبة. عنوان المثال هو النطاق العام للمشروع؛ لا تنفذ اختبارات كتابة عليه. تحتاج الإضافات الجديدة نشرًا على السيرفر المقصود قبل الاعتماد عليها. لا تضع اتصال قاعدة البيانات أو مفاتيح Google/Apple الخاصة أو مزود النموذج داخل حزمة الجوال.

المشروع مستقل بحزمة واعتماديات وlockfile خاصين حتى لا تتعارض أدوات React Native مع فحص Next.js في جذر المستودع. تولّد المشاريع الأصلية من `app.config.ts` وconfig plugins؛ لا تعدل Android أو iOS المولدين يدويًا.

## مطابقة واجهة الويب

تستخدم الرئيسية شعار سوق حمد، وشرائح المجموعات والتصنيفات والخيارات والموديلات، وبطاقات الإعلانات الأفقية، وأيقونة حمد القابلة للسحب، وشريط التنقل الوسطي بالترتيب نفسه. التصنيفات والخيارات والماركات والموديلات والمدن والسياسات مأخوذة من التعريفات العامة للمشروع عبر `pnpm.cmd sync:catalog`؛ لا تُنسخ صفحات الويب إلى الحزمة. إذا أعاد `/api/mobile/bootstrap` حالة 404، يستخدم التطبيق هذه القائمة العامة فقط، بينما تظل الإعلانات والحسابات والمحادثات عبر API السيرفر مباشرة.

تتطلب متابعة الإعلانات المشابهة نشر مسار `GET/POST /api/marketplace/listings/{id}/similar-follow` الموجود في مصدر السيرفر. أُضيف طلب أقرب مدينة بإذن ظاهر أثناء الاستخدام؛ يحسب الجهاز المدينة الأقرب من إحداثيات الموقع العامة نفسها، ويرسل اسم المدينة إلى API فقط.

## بناء أندرويد وآيفون

```powershell
# نسخة تطوير أصلية لأندرويد؛ تحتاج Android SDK وJDK المتوافقين.
pnpm.cmd android
# نسخة تطوير أصلية لآيفون؛ يشغّل هذا الأمر على Mac مع Xcode.
pnpm.cmd ios
```

تسجيل Google الأصلي وAPNs/FCM يحتاج development build أو حزمة إصدار، وليس Expo Go. على Windows يمكن بناء Android محليًا، وبناء iOS على Mac أو خدمة بناء macOS.

لبناء APK تجريبي محلي من جذر المستودع بعد تثبيت الاعتماديات والأدوات:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-android-preview.ps1
```

يمكن تمرير `-ApiUrl` لتحديد سيرفر التجربة. هذا الأمر يتجاهل ملفات dotenv ويستخدم قيم بيئة العملية أو العنوان الافتراضي، ويبني نسخة arm64 موقّعة بمفتاح debug محلي. يحفظ الملف وSHA256 وسجل البناء داخل `.data/native-mobile`؛ لا يرفع نسخة إلى المتجر.

يضبط المشروع CMake على `3.31.6` عبر config plugin، ويستخدم تثبيت pnpm بنمط `hoisted` داخل هذا المجلد لتقصير مسارات المكتبات الأصلية على Windows. يضبط plugin إضافي خاص بـWindows حد مسارات ملفات C++ إلى `200` عبر خيار Expo الأصلي. ثبّت إصدار CMake من Android SDK Manager إذا لم تنزّله أداة البناء تلقائيًا، ثم أعد `expo prebuild` عند تغيّر التهيئة الأصلية.

ملفات EAS مجهزة: development وpreview وproduction، مع إدارة أرقام البناء في EAS. عند اختيار البناء السحابي، يربط مالك المشروع حساب Expo ومشروعه وبيانات التوقيع ثم يستخدم:

```powershell
pnpm.cmd dlx eas-cli build --profile preview --platform android
pnpm.cmd dlx eas-cli build --profile production --platform ios
```

الإعداد الافتراضي للتطوير يستخدم `com.souqhamad.app.dev` لتجنب استبدال تطبيق الإنتاج على الجهاز. production يستخدم `com.souqhamad.app`؛ يجب التحقق من ملكيته ومفاتيح التوقيع قبل رفع حزمة إلى المتاجر. لا يوجد نشر تلقائي أو حساب سحابي مفترض في المصدر.

## المصادقة والإشعارات

- **Google:** يقرأ التطبيق Web Client ID العام من `/api/auth/google/native-config` ولا يحمل سر Google. حتى يعمل APK التجريبي الحالي، سجّل Android OAuth في مشروع Google نفسه بمعرف الحزمة `com.souqhamad.app.dev` وبصمة SHA-1 `5e8f16062ea3cd2c4a0d547876baa6f38cabf625`؛ ثم اجعل `GOOGLE_NATIVE_CLIENT_ID` (أو `GOOGLE_CLIENT_ID`) على السيرفر من نوع Web ومطابقًا للجمهور الذي يتحقق منه السيرفر. إصدار المتجر يستخدم الحزمة `com.souqhamad.app` وتوقيعًا مختلفًا، لذا يحتاج بصمة شهادة الإصدار الفعلية. على iOS يلزم `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` و`EXPO_PUBLIC_GOOGLE_IOS_URL_SCHEME` قبل إعادة بناء التطبيق.
- **Apple:** entitlement الخاص بـSign in with Apple، و`APPLE_NATIVE_CLIENT_ID` المطابق لمعرف الحزمة في السيرفر مع مفاتيح الفريق. التطبيق يستخدم challenge وPKCE وnonce مرتبطًا بالتدفق، ويعرض Apple على iOS عند إعلان السيرفر توفره.
- **FCM:** مرر مسار ملف إعداد تطبيق Firebase عبر `GOOGLE_SERVICES_JSON` أثناء البناء. حساب خدمة الإرسال ومفتاحه يبقيان في السيرفر.
- **APNs:** يطابق bundle ID وبيئة sandbox/production إعداد السيرفر وprovisioning. تفعيل الإشعارات بإجراء صريح من المستخدم داخل صفحة الإشعارات.
- **الروابط:** حدّث assetlinks بشهادات التطبيق النهائية وأنشئ apple-app-site-association على النطاق لتعمل App Links وUniversal Links.

كل تغيّر أصلي أو config plugin يتطلب إعادة بناء الحزمة. حفظ الجلسة في Keychain/Keystore، وإرسال Bearer دون cookie مشتركة، ومسح cache الحساب عند الخروج أو انتهاء الجلسة. السيرفر الحالي يصدر جلسة مدتها 14 يومًا ولا يوفر refresh أو إلغاء Bearer لكل جهاز؛ التطبيق يعيد التحقق عند الاستئناف، ولا يدعي أن logout الحالي يلغي نسخة مسروقة من الرمز. تطوير جلسات أجهزة وإلغاء تفويض Apple عند حذف الحساب من متطلبات تقوية الإطلاق العام.

نسخة `.dev` تحتاج إعدادات المزودين المطابقة لمعرفها في سيرفر التجربة، ومنها `APPLE_NATIVE_CLIENT_ID` و`APNS_BUNDLE_ID`؛ إعدادات حزمة الإنتاج لا تفترض صلاحيتها لحزمة التجربة.

## ما يتضمنه التطبيق

الرئيسية والبحث والتصفية، تفاصيل الإعلان وصوره ومفضلته وبلاغه والتواصل، ملف المعلن وتقييمه ومتابعته، المفضلة وقوائم المتابعة، إنشاء الإعلان اليدوي والصور والمعاينة والنشر وإدارته، حمد لإعداد المسودات والمساعدة الموثقة، المحادثات والحظر والبلاغ والحذف ومشاركة الرقم، الحساب وصورته وحذفه، الإشعارات والرسوم والسياسات.

البيانات تأتي من API الفعلية، دون إعلانات أو أسعار أو صور منتجات تجريبية في التطبيق. ظهور التصنيفات والسياسات يعتمد على `/api/mobile/bootstrap`. تستند إجراءات الحظر والملكية والعمولات والإشراف إلى السيرفر. الدفع الحالي تعليمات دفع يدوية من السيرفر، وليس بوابة دفع جديدة.

البث يتوقف في الخلفية ويعيد المزامنة عند العودة. طلب تفاصيل المحادثة يعلّمها مقروءة؛ لذلك يتوقف عند مغادرة الشاشة. SSE الحالية على السيرفر محلية للعملية؛ إعادة الجلب الدورية وسيلة تعافٍ وليست ضمانًا لتسليم كل الأحداث. فك تسجيل push دون إنترنت قد يتأخر حتى عودة الاتصال.

تاريخ حمد نصي ومشفّر محليًا ومربوط بالحساب وعنوان السيرفر، مع حد للاحتفاظ والحجم ومسح عند الخروج. الصور وأجزاء الأدوات لا تحفظ في التاريخ. لا توجد مزامنة تاريخ حمد بين الأجهزة في السيرفر الحالي. النشر وكل إجراءات السوق الحساسة تتم بأزرار المستخدم؛ لا يملك حمد أدوات البحث أو التسعير أو التفاوض أو إدارة الحساب.

## التحقق

```powershell
pnpm.cmd check
node --experimental-strip-types --test tests/native-transport.test.mjs
node --test tests/*.test.cjs
pnpm.cmd export
node tests/browser-smoke.cjs
```

فحص البث يستخدم حالات تجزئة UTF-8 وCRLF وإعادة الاتصال وحدود سياق حمد. فحص الرفع يمرر بايتات الصور عبر محوّل multipart الحقيقي في Expo مع تمويه إمكانات الجهاز والشبكة. اختبارات السيرفر الإضافية في `../SmartStoreAI/tests/native-mobile-api.test.ts` و`../SmartStoreAI/tests/apple-native-auth.test.ts`، وتعمل عبر harness المشروع المعزول. ثُبّت APK الحالي واختُبر عرضه على Android فعلي؛ تبقى تجربة OAuth والكاميرا ورفع الصور والإشعارات بإعدادات المالك واختبار iOS بتوقيع صالح قبل النشر للمتاجر.

النتائج وحدودها في [سجل التحقق](docs/native-mobile-verification-2026-10-23.ar.md)، وللتصميم التفصيلي: [وثيقة البنية](docs/native-mobile-architecture.ar.md). لم تُنفذ شاشات الإدارة داخل تطبيق الجوال؛ إدارتها الحالية في الويب تظل مستقلة.
